# 02 启动流程与固定步循环

## 本章覆盖范围

本章按参考引擎源码真实执行顺序，梳理：

1. 程序入口、命令行参数解析、工作目录与资源根定位；
2. 启动检查（配置 / 资源挂载 / 规则 / 美术 / 地图 / 世界）与子系统初始化先后；
3. 会话类型划分（完整有窗战局会话、无窗口检查入口、平台私有设备适配）；
4. 主菜单 → 战役 / 遭遇战 / LAN / 互联网菜单 → 战局状态的提交链路；
5. 固定步模拟循环：时钟配对、tick 推进、确定性哈希阶段、受限任务执行器接入点；
6. 一帧内的阶段划分（输入 → 模拟 → 资源/几何准备 → 绘制 → 呈现），菜单态与战局态差异，呈现后端选择与回退边界；
7. 退出与会话收尾（音频 / 缓冲 / 偏好 / 存档 / 回放 / 快照）。

## 1. 程序入口

### 1.1 入口函数与进程附加

参考引擎入口在 `src/runtime/host/RuntimeMain.cpp`：

- Windows 下使用 `WinMain`（`src/runtime/host/RuntimeMain.cpp:1009`），先 `AttachConsole(ATTACH_PARENT_PROCESS)` 复用开发者控制台，重定向 stdout/stderr 后转交 `runRuntimeApplication`（`src/runtime/host/RuntimeMain.cpp:1012-1023`）；
- 非 Windows 下使用标准 `main`（`src/runtime/host/RuntimeMain.cpp:1026-1028`）；
- 两个入口最终都进入 `runRuntimeApplication`（`src/runtime/host/RuntimeMain.cpp:743`）。

进程级最先执行的是 DPI 感知设置 `enableRuntimeDpiAwareness()`（`src/runtime/host/RuntimeMain.cpp:34-53`）：在任何窗口/GDI 表面创建之前，通过 `GetProcAddress` 动态解析 `SetProcessDpiAwarenessContext`，设置 Per-Monitor V2 感知（句柄值 `-4`），避免位图虚拟化把整帧线性缩放导致单像素体素细节模糊。该函数仅在 `_WIN32` 下有实现体，属平台私有适配。

### 1.2 命令行解析

解析器为 `parseRuntimeCommandLine`（`src/runtime/host/RuntimeMain.cpp:137`），逐 token 遍历 `argv[1..]`：

- 取值型参数由 `readRequiredValue` 统一校验：缺值报错；下一个 token 以 `--` 开头视为「把选项值误写成另一个选项」并报错（`src/runtime/host/RuntimeMain.cpp:104-126`）；
- 非负整数由 `parsePositiveIntOrZero` 解析，解析失败回落 `0`（`src/runtime/host/RuntimeMain.cpp:128-135`）；
- 未知参数以 `Unknown runtime option: <token>` 终止解析（`src/runtime/host/RuntimeMain.cpp:617-618`）；
- `--help` / `-h` 提前返回并打印帮助（`src/runtime/host/RuntimeMain.cpp:143-146`、`624-708`）。

解析结果结构 `RuntimeCommandLine`（`src/runtime/host/RuntimeMain.cpp:55-102`）分为三类：

1. 呈现与窗口选项：`skirmishWindow`、`presentation`（`FrameBackendOptions`）、`gpuBudgetMib`、`frameWorkers`；
2. 配置覆盖项 `RuntimeConfigOverrides overrides`：路径、窗口尺寸、tick 频率、目标帧率、回放事件输出；
3. 大量诊断 / smoke 开关（本章流程梳理中不作为正常路径）。

### 1.4 配置加载与路径定位

#### 1.4.1 配置结构与合并优先级

运行配置由 `RuntimeConfig` 承载（`src/runtime/config/RuntimeConfig.h:11-128`），覆盖项为 `RuntimeConfigOverrides`（`src/runtime/config/RuntimeConfig.h:130-141`）。合并优先级为「内置默认值 → INI 文件 → 命令行覆盖」：覆盖对象中的非空字符串与正整数覆盖对应设置（`src/runtime/config/RuntimeConfig.cpp:32-38`、`401-440`；API 说明见 `API.md:349`）。

1. 解析工程根 `projectRoot` 与配置文件绝对路径（`src/runtime/config/RuntimeConfig.cpp:132-137`）；

3. 对路径类字段做工程根相对路径解析（`src/runtime/config/RuntimeConfig.cpp:401-432`）；

#### 1.4.3 工程根与路径解析

路径定位模块为 `src/runtime/config/RuntimeConfigPaths.*`，不含目录枚举、大小写折叠或资源选择（`src/runtime/config/RuntimeConfigPaths.h:6-8`）：

1. **工程根发现** `runtimeConfigProjectRoot`（`src/runtime/config/RuntimeConfigPaths.cpp:38-50`）：把当前工作目录与其全部祖先、可执行文件目录与其全部祖先加入候选；判定标准 `isProjectRoot`：同时存在 `local_data` 与 `CMakeLists.txt`，且存在 `RedAlert2` 或 `.git`（`src/runtime/config/RuntimeConfigPaths.cpp:14-18`）；均不命中时回落候选列表第一项，再回落当前目录。
2. **配置/资源路径解析** `runtimeResolveConfigPath`（`src/runtime/config/RuntimeConfigPaths.cpp:52-62`）：空值返回空；绝对路径直接规范化；相对路径先取「当前工作目录 / 值」，存在则用之，否则取「工程根 / 值」；`weakly_canonical` 失败时保留词法规范化回落。

## 2. 启动检查与子系统初始化顺序

### 2.1 正常启动的分发顺序

`runRuntimeApplication` 在解析参数、完成组合约束检查后，执行：

1. `loadRuntimeConfig(commandLine.overrides)` 装载配置（`src/runtime/host/RuntimeMain.cpp:790`）；
2. 应用 `--skip-main-menu` / `--skip-skirmish-menu`（`src/runtime/host/RuntimeMain.cpp:791-797`）；
3. 依次判断各类诊断 / smoke 入口（菜单 UI、战役、联机、规则、模拟等，`src/runtime/host/RuntimeMain.cpp:799-992`）；这些入口不进入正常有窗战局；
4. 若 `--skirmish-window sdl3`：先走 SDL3 遭遇战菜单 `runRuntimeSkirmishMenuSdl3`，接受后 `applyRuntimeSkirmishSelection` 并关闭菜单标记，再进入战局窗口（`src/runtime/host/RuntimeMain.cpp:994-1002`）；
5. 正常路径进入 `runRuntimeWindowWithMultiplayerFailureRecovery`（`src/runtime/host/RuntimeMain.cpp:1003`）：外层 `for(;;)` 包裹 `runRuntimeWindow`，联机可见失败时弹出恢复重试对话框；非 Win32 仅打印错误并返回（`src/runtime/host/RuntimeMain.cpp:710-741`）。

`runRuntimeWindow` 有三个重载（声明 `src/runtime/host/RuntimeShell.h:286-300`）：默认无桥接、无呈现选项；最终四层实现把 `FrameBackendOptions` 透传到会话（`src/runtime/host/RuntimeMain.cpp` 调用点 `718`）。最外层包装按 `RuntimeWindowCompletion::ReturnToMainMenu` 决定是否重开会话；联机桥接会话结束后不可回收到离线菜单循环（`src/runtime/host/RuntimeShell.cpp:89083-89112`）。

### 2.2 会话内初始化阶段（`runRuntimeWindowSession`）

会话主体为 `runRuntimeWindowSession`（`src/runtime/host/RuntimeShell.cpp:87720`）。其内部严格顺序如下，每步附出处：

| 序号 | 阶段 | 关键动作 | 出处 |
| --- | --- | --- | --- |

## 3. 会话类型与共享生产状态边界

### 3.1 完整有窗战局会话

- 入口：`runRuntimeWindow` 系列重载 → `runRuntimeWindowSession`（`src/runtime/host/RuntimeShell.cpp:87720`）。
- 承载：`RuntimeWindowState`（内含配置、启动报告、世界/剧场/美术/规则/地图事实、战斗、经济、触发器、音频、渲染缓存等）；共享生产状态基类为 `RuntimeGameSessionState`（`src/runtime/session/detail/RuntimeProductionHostState.h:4-80`），其上叠加 `RuntimeProductionHostState` 扩展命令、几何、操作等细节（`src/runtime/session/detail/RuntimeProductionOperations.h:238` 前置声明）。
- 生命周期：外层 `runRuntimeWindow` 按返回完成态决定退出进程或回主菜单重开会话（`src/runtime/host/RuntimeShell.cpp:89083-89112`）。

### 3.2 无窗口检查入口（非完整会话）

参考引擎不存在独立的 headless 战局主循环进程入口。无窗口路径均为启动检查或诊断：

- `--smoke-test`：`buildRuntimeStartupReport` 后打印报告，不开窗口，退出码 0/1 对应成功/失败（`src/runtime/host/RuntimeMain.cpp:862-866`；API 说明 `API.md:1077`）；
- 其余 `--*-smoke-test` / `--*-integration-smoke-test` 分支在 `src/runtime/host/RuntimeMain.cpp:868-992`，属诊断夹具路径；
- `src/runtime/session/headless/` 下的生产文件是设备与查询适配，不是会话循环：
  - `RuntimePortableSessionDevices.cpp`：语音/ wave/异步音频设备全部返回不支持（`ready()=false`、`lastError()=-1`、`open/play/queue/stop/close` 空实现，`src/runtime/session/headless/RuntimePortableSessionDevices.cpp:12-21`）；宽字符/UTF-8 转换直接抛 `std::logic_error`（`src/runtime/session/headless/RuntimePortableSessionDevices.cpp:28-34`）；
  - `RuntimeHeadlessResourceQueries.cpp`：无原生几何帧的地形 TMP 备忘录与资源查询实现（`src/runtime/session/headless/RuntimeHeadlessResourceQueries.cpp:25-30`）；
  - `RuntimeHeadlessMapAuthority.cpp`：出生点限制解析委托给菜单详情实现（`src/runtime/session/headless/RuntimeHeadlessMapAuthority.cpp:3-5`）。
- `src/runtime/session/win32/` 为对应原生实现：异步 SFX、EVA wave、壳音乐 wave 设备工厂（`src/runtime/session/win32/RuntimeNativeSessionDevices.cpp:18-34`），原生几何结构在 `RuntimeNativeSessionGeometry.h`。

### 3.3 共享生产状态边界

`RuntimeGameSessionState` 同时被有窗会话、联机桥接会话、存档/回放恢复与诊断夹具复用；边界约定：

- 世界对象统一由 `GameWorld::WorldObjectInstance` 承载，步兵/载具/海军/两栖/飞行器/建筑由规则标志与系统归属区分（见规范第 4 节；结构字段清单见 `src/runtime/session/detail/RuntimeProductionHostState.h:4-80`）；
- 快照活动状态通过 RAII 作用域 `RuntimeSnapshotActiveStateScope` 绑定到全局指针，析构恢复上一层（`src/runtime/session/detail/RuntimeProductionOperations.h:10075-10086`）；
- 呈现/输入偏好（滚动速度、细节等级、音量、键位等）不进入确定性匹配权威，可在战役/遭遇战/联机运行中修改（`src/runtime/config/RuntimeConfig.h:77-94` 注释）。

## 5. 固定步模拟循环

### 5.1 时钟与游戏速度定时

#### 5.1.1 规则帧与固定 tick

- 规则秒定义：一个规则分钟为 900 个零售逻辑帧，规则帧率 15 fps（`src/runtime/timing/RuntimeRuleTime.h:11-13`）；
- 帧↔tick 换算：`runtimeRuleFramesToTicks` / `runtimeRuleFrameAtTick` / `runtimeRuleFramesElapsed` / `runtimeRuleIntervalCrossed`，`fixedTickHz` 夹紧 `[1,1000]`（`src/runtime/timing/RuntimeRuleTime.h:15-38`）。

#### 5.1.2 游戏速度定时

`RuntimeGameSpeedTiming`（`src/runtime/timing/RuntimeGameSpeedTiming.h:12-54`）：

| 成员 | 类型 | 含义 |
| --- | --- | --- |
| `nativeWaitQuanta` | `int` | 零售 GameOptions 等待计数；`0` 表示不限速（`unlimited()`） |
| `secondsPerTick` | `double` | 单 tick 墙钟秒数 |
| `accumulate(previous, elapsed, maximumTicks)` | 方法 | 累加经过时间，按最大追赶 tick 数封顶；不限速恒返回 0 |
| `ready(accumulated, advanced, maximumTicks)` | 方法 | 是否可再推一个 tick；含浮点 roundoff 余量 |
| `consume(accumulated, ticks)` | 方法 | 扣除已消费 tick；不限速清零 |
| `roundedTickRate()` | 方法 | 诊断用四舍五入频率，调度实际必须用 `secondsPerTick` |

构造器 `runtimeGameSpeedTiming(slider, fixedTickHz)`（`src/runtime/timing/RuntimeGameSpeedTiming.h:56-64`）：等待量子 `= 6 - clamp(slider,0,6)`；`secondsPerTick = waitQuanta × 0.016 × 15 / max(1,fixedTickHz) / 1.5`。即速度滑杆只改墙钟等待，不改固定模拟频率。

### 5.3 主循环骨架

循环起点 `while (running)`（`src/runtime/host/RuntimeShell.cpp:88558`），每轮：

1. **排空消息**：`hostLoop.drainMessages()`，返回 `false` 即退出（`88563-88566`）；
2. **联机断连后处理**：本地认输后分离桥接、关闭 LAN（`88568-88577`）；
3. **追赶上限与速度定时**：`maxSimulationCatchUpTicks` 按联机/离线取值；`runtimeGameSpeedTiming(gameSpeed, fixedTickHz)` 构造本帧定时；墙钟经过时间 `elapsed` 累加进 `tickAccumulator`（`88578-88592`）；
4. **联机 pump 分支**：主机在 ready 时请求推进；`bridge.pump(requestHostAdvance, 0)`；失败标记致命停止；提交 tick 后校验与本地 `state.tick` 一致，推进水沫状态，主机消费累加器；客户端/观战者墙钟不成为模拟权威，累加器清零（`88595-88697`）；
5. **暂停分支**：非联机且（战局内菜单打开或战局已结束）时累加器清零，模拟暂停（`88698-88703`）；
6. **呈现预算**：`RuntimePresentationWorkBudget` 按帧步长、上次绘制耗时、模拟耗时估计、请求呈现频率构造；余量服务资格受预算开关、不限速、菜单、战局结束、待播视频、参考模式等条件约束（`88704-88729`）；
7. **模拟批次**：见 5.4；
8. **音频呈现时钟与空间混音**：`advanceRuntimeWorldAudioPresentationClocks`、`advanceRuntimeSpatialAudioMixes`（`88829-88833`）；
9. **待播战役视频**：逐部播放，期间停止 EVA/SFX/世界音频/音乐，结束后补水并重置时钟（`88835-88898`）；
10. **UI 呈现推进**：`advanceRuntimeUiPresentation`；tick 推进则标记重绘（`88904-88907`）；
11. **帧截止与绘制排队**：按 `targetFps` 计算 `frameStepClock`，到点则 `InvalidateRect`；benchmark 窗口直接 `SendMessageW(WM_PAINT)`；普通窗口 `UpdateWindow` 服务低优先级 WM_PAINT（`88909-88941`）；
12. **FPS 统计与音乐保活**：每秒采样绘制/渲染帧数，`ensureRuntimeMusicPlaying`，重置性能峰值（`88945-88963`）；
13. **余量记账与空闲休眠**：按模拟/绘制/额外服务耗时更新余量估计；满足条件则 `hostLoop.sleepForIdleSlice()`（`88967-89002`）。

### 7.3 存档 / 回放 / 快照收尾

- **存档**：退出会话不自动写档。存档由 UI 命令 `dispatchRuntimeSaveLoadFromUi` 触发：离线走默认存档路径 `saveRuntimeState`/`loadRuntimeState`；联机走 `beginRuntimeMultiplayerFileOperation`（`src/runtime/host/RuntimeShell.cpp:9403-9415`）。存档文档解析边界见 `src/runtime/persistence/RuntimeSaveDocument.h:5-9`；载入事务见 `src/runtime/persistence/RuntimeLoadTransaction.*`。
- **回放**：完整回放由 `RuntimeMatchReplayWriter`/`Reader` 在回放沙箱/会话内完成，强制 Finish 记录区分完整录制与中断文件，信封以 SHA-256 链式串联（`src/runtime/replay/RuntimeMatchReplay.h:45-48`；写入 Finish 置 `finished_` 见 `RuntimeMatchReplay.cpp:230-232`）。主战局循环内仅写运行时事件快照流，输出路径由 `RuntimeReplayEventSnapshot` / `runtimeReplayEventOutputPath` 配置（`src/runtime/host/RuntimeShell.h:302-306`；`RuntimeConfig.h:126-127`）。
- **快照作用域**：`RuntimeSnapshotActiveStateScope` 析构恢复上一层全局活动状态指针（`src/runtime/session/detail/RuntimeProductionOperations.h:10081-10083`）；联机桥接由 `RuntimeMultiplayerRuntimeAttachmentState` 守卫在套接字/会话析构前卸载回调（`src/runtime/host/RuntimeShell.cpp:87734-87737`、`88324-88350`）。
- **资源释放**：缓冲释放见 7.2；D3D11 呈现器资源寿命在 `src/runtime/presentation/win32/D3D11ResourceLifetimeWin32.inl`；地图/菜单光栅缓存分别在 `D3D11MapPresentWin32.inl` / `D3D11MenuPresentWin32.inl`。

## 本章缺口 / 参考引擎未覆盖项

1. **无独立 headless 战局主循环**：`src/runtime/session/headless/` 仅提供资源查询与不支持设备桩；语音、wave、异步音频在 headless 下全部返回未就绪/失败，文本转换抛 `std::logic_error`（`src/runtime/session/headless/RuntimePortableSessionDevices.cpp:12-34`）。参考引擎当前状态：不存在无窗口跑完整模拟帧循环的生产入口。
2. **`auto` 后端未实现硬件自适应**：`auto` 当前固定选择软件并记录原因，未做 GPU 能力探测后选硬件（`src/runtime/host/RuntimeMain.cpp:774-777`；`API.md:1075`）。
3. **SDL3 仅限遭遇战菜单**：战局窗口固定 Win32；SDL3 只加载相邻已校验包内函数，不使用 PATH/当前目录库，也不取 SDL 原生 HWND（`src/runtime/window/sdl3/RuntimeSdl3Window.cpp:21-30`）。参考引擎未提供 SDL3 战局窗口。
4. **本地启动链不播种模拟随机源**：`simulationRandomSeed` 由联机权威下发；安全随机字节仅网络会话/传输使用（`src/runtime/config/RuntimeConfig.h:24-36`；`src/core/security/RuntimeSecureBytes.cpp:88`）。离线单机的确定性随机来源在本章启动链中未看到独立初始化点。
5. **视频助手为独立进程**：Bink 播放由独立 x86 视频助手承担（`API.md:1047`）；运行时通过 `runRuntimeBinkVideo` 调用，其内部进程协议与失败恢复细节不在本章静态阅读范围内。
6. **退出不自动存档 / 不自动写完整回放**：存档与完整回放写入均由命令或回放沙箱触发；主循环只输出事件快照流（见 7.3）。
7. **跨平台战局窗口未实现**：非 `_WIN32` 下 `WinMain` 走 `main`，但战局窗口宿主、D3D11 呈现、定时器分辨率、进程性能作用域等均为 Win32 私有实现；Linux 侧仅有安全随机后端与 headless 桩，未看到可运行的原生窗口战局路径。
8. **诊断夹具不计入行为依据**：`src/runtime/host/RuntimeMain.cpp:148-338` 的各类 `--*-smoke-test`、`src/runtime/performance/diagnostics/`、`src/runtime/persistence/diagnostics/` 等仅佐证格式与边界约定，正常启动流程不得引用其结论。
9. **本章未展开的下游细节**：规则/美术/剧场 INI 字段映射、地图解码、SHP/VXL 编解码、寻路队列预算、联机 lockstep 命令与快照版本、侧边栏/雷达/覆盖层绘制顺序，分别由后续章节覆盖；本章仅标注其在启动与帧循环中的接入点。
