# 09 · 单位总览与分类

## 本章覆盖范围

本章梳理参考引擎中「步兵 / 陆地载具 / 海军 / 两栖 / 飞行器」五类可移动作战单位（以及与它们对照的建筑）在规则层、运行时层、移动层、生产层、战斗层、视野层、持久化层的统一归属方式，给出规则列表入口、运行时字段分组、移动模式判定、生命周期阶段与通用接入点。

本章不展开各子类的动画帧选择、绘制细节与声音映射；那些内容分别见 [10-步兵.md](10-步兵.md)、[11-陆地载具.md](11-陆地载具.md) 与后续渲染章节（计划中的 17 章）。

## 1. 现实前提：参考引擎没有单位子类 C++ 继承树

**结论先行（必须照此理解后续所有章节）：** 参考引擎没有为步兵、陆地载具、海军、两栖、飞行器、建筑分别建立独立 C++ 类；运行时物件统一为 `WorldObjectInstance`，不存在 `RuntimeInfantry`、`RuntimeVehicle`、`RuntimeNaval`、`RuntimeAmphib` 之类的独立实体类（全仓正则核对未找到对应类声明，参见 01 章 4.3 节末注）。

- 运行时结构：`struct WorldObjectInstance`，`src/world/model/GameWorld.h:98`。
- 种类枚举仅有三值：

| `WorldObjectKind` 取值 | 出处 | 对应规则列表 |
| --- | --- | --- |
| `Structure` | `GameWorld.h:14` | `BuildingTypes` |
| `Unit` | `GameWorld.h:15` | `VehicleTypes` / `AircraftTypes` |
| `Infantry` | `GameWorld.h:16` | `InfantryTypes` |

六类（步兵 / 陆地载具 / 海军 / 两栖 / 飞行器 / 建筑）由「规则列表归属 + 规则标志 + 移动模式」共同推导，而不是 C++ 继承。本章先讲清这一现实；10、11 两章在此前提下按规则标志与系统归属展开。

## 2. 规则列表归属与 `WorldObjectKind` 映射

### 2.1 四个类型列表段的加载入口

四个类型列表段在 `RulesDatabase.cpp` 中由同一装载流程读取，段名原样照抄：

| 类型列表段 | 装载调用 | 规则容器 | 出处行号 |
| --- | --- | --- | --- |
| `InfantryTypes` | `loadUnitList(ini, "InfantryTypes", infantryTypes_)` | `std::vector<UnitType> infantryTypes_` | `RulesDatabase.cpp:2954` |
| `VehicleTypes` | `loadUnitList(ini, "VehicleTypes", vehicleTypes_)` | `std::vector<UnitType> vehicleTypes_` | `RulesDatabase.cpp:2963` |
| `AircraftTypes` | `loadUnitList(ini, "AircraftTypes", aircraftTypes_)` | `std::vector<UnitType> aircraftTypes_` | `RulesDatabase.cpp:2972` |
| `BuildingTypes` | `loadBuildingList(ini, "BuildingTypes", buildingTypes_)` | `std::vector<BuildingType> buildingTypes_` | `RulesDatabase.cpp:2981` |

步兵 / 车辆 / 飞行器三类在规则层**共用同一个规则结构 `UnitType`**（`RulesDatabase.h:503`），建筑为独立的 `BuildingType`（`RulesDatabase.h:791`）。列表装载后还会收集类型 ID 列表、修补缺失段：`RulesDatabase.cpp:2956-2957`、`2964-2966`、`2973-2975`、`2982-2984`。

### 2.2 列表段 → `objectKind` 字符串 → `ObjectCapability` 标志

`loadUnitType` 接收一个 `objectKind` 字符串参数（`RulesDatabase.cpp:3813-3818`），其取值在列表装载循环中按段名确定（`RulesDatabase.cpp:5454-5459`）：

| 列表段 | `objectKind` | `ObjectCapability` 写入 | 出处 |
| --- | --- | --- | --- |
| `InfantryTypes` | `"infantry"` | `capability.infantry = true` | `RulesDatabase.cpp:5455-5456`；`RulesDatabase.cpp:1097` |
| `VehicleTypes` | `"vehicle"`（缺省） | `capability.vehicle = true` | `RulesDatabase.cpp:5454`；`RulesDatabase.cpp:1098` |
| `AircraftTypes` | `"aircraft"` | `capability.aircraft = true` | `RulesDatabase.cpp:5457-5458`；`RulesDatabase.cpp:1099` |

`ObjectCapability` 结构定义于 `RulesDatabase.h:84-105`，除 `infantry/vehicle/aircraft/building` 外还携带 `naval`、`waterBound`、`turret`、`crusher`、`crushable`、`omniCrusher`、`omniCrushResistant`、`repairable`、`canPassiveAquire`、`canRetaliate`、`speed`、`speedType`、`movementZone`、`locomotor`、`category` 等运行时派生标志。能力填充函数：`unitCapabilityForObject`（`RulesDatabase.cpp:1091-1116`）。

地图作者物件在地图数据库中先被解析为四种结构（`src/data/maps/MapDatabase.h`），再由 GameWorld 构造函数映射到运行时实例：

| --- | --- | --- | --- | --- |

## 4. 移动模式总览

### 4.1 寻路移动模式枚举

`PathMovementMode` 定义于 `src/simulation/navigation/pathfinding/PathGoalTypes.h:8-13`：

| 枚举值 | 含义 |
| --- | --- |
| `Ground` | 地面 |
| `Naval` | 海军（水面航行） |
| `Amphibious` | 两栖 / 悬浮 |
| `Air` | 空中 |

### 4.2 运行时分类判定

运行时分类函数集中在 `src/simulation/movement/ground/RuntimeMovementClassification.h`：

- 空中轮廓判定 `runtimeUnitAirMovementProfile`（`RuntimeMovementClassification.h:77-91`）：`jumpJet` 为真、`consideredAircraft` 为真、`movementZone` 含 `fly`、`speedType` 含 `winged` / `fly`、或 `locomotor` 含 `fly`，任一成立即视为空中。
- 移动模式轮廓 `runtimeUnitMovementModeProfile`（`RuntimeMovementClassification.h:93-104`），判定顺序：
  1. 空中轮廓成立 → `PathMovementMode::Air`；
  2. `speedType` / `movementZone` 含 `amphib` 或 `hover` → `PathMovementMode::Amphibious`（悬浮优先于显式海军 / 水面属性，见 `:96-99` 注释）；
  3. `naval` / `waterBound` 为真，或 `speedType` 含 `float` / `water`、`movementZone` 含 `water` → `PathMovementMode::Naval`；
  4. 其余 → `PathMovementMode::Ground`。
- 地形通行百分率 `runtimeUnitLandPercentProfile`（`RuntimeMovementClassification.h:106-122`）：按 `hover` / `amphib` / `floatBeach` / `float` / `track` / `wheel` / `foot` 关键词分别取 `LandType` 的对应通行率；步兵或 `foot` 关键词走 `foot`，其余按 `crusher` 取 `track` / `wheel`。

### 4.3 规则侧输入键

移动分类的规则输入全部来自 `UnitType`（`RulesDatabase.cpp:3951-3953`、`:3979`、`:4080-4081`）：

| `SpeedType` | `speedType` | `RulesDatabase.cpp:3951` |
| `MovementZone` | `movementZone` | `RulesDatabase.cpp:3952` |
| `Locomotor` | `locomotor` | `RulesDatabase.cpp:3953` |
| `JumpJet` | `jumpJet` | `RulesDatabase.cpp:3955` |

寻路目标上下文枚举位于 `src/simulation/navigation/pathfinding/PathGoalTypes.h`；地形格子通行属性（水面 / 岸边 / 桥 / 坡 / 悬崖 / 资源）见同文件 `PathTerrainCell`（`PathGoalTypes.h:15-27`）。

## 5. 单位生命周期

下表按阶段串联从地图放置到移除的完整链路，并标注各阶段对应的生产系统文件。纯诊断夹具（`diagnostics/`、`*.Smoke.*`）不计入。

### 5.1 地图放置（作者物件入世界）

1. 地图 INI 解析为 `MapUnitObject` / `MapInfantryObject` / `MapAircraftObject` / `MapStructureObject`（`MapDatabase.h:155/172/190/139`）。
2. GameWorld 调用 `makeUnitInstance` / `makeInfantryInstance` / `makeAircraftInstance` / `makeStructureInstance` 生成 `WorldObjectInstance`，换算朝向、健康度、作者等级、是否在桥上（`GameWorld.cpp:337-429`）。
3. 初始健康度按地图 0..256 比例与规则 `Strength` 计算：`applyInitialMapHealth`（`GameWorld.cpp:300-306`）。

### 5.2 出厂交付（生产完成 → 世界物件）

1. 生产队列按车道推进：车道枚举 `RuntimeProductionLane`（`Structures/Armory/Infantry/Vehicles/Aircraft/Ships`，`RuntimeProductionLanes.h:18-25`）；单位按 `RuntimeProductionUnitClass` 映射车道，载具按 `naval` / `waterBound` 拆到 `Ships` 或 `Vehicles`（`RuntimeProductionLanes.cpp:249-264`）。
2. 出厂租约由 `RuntimeFactoryDeliveryState` 管理（`RuntimeFactoryDeliveryState.h:133-174`），含宿主、泊位、车道、订单序列号、出厂格、陆地 / 海军域（`RuntimeFactoryDeliveryDomain::Land/Naval`，`:30-33`）。
3. 出厂动作与门 / 屋顶动画：`RuntimeFactoryEgressMotion.inl`、`RuntimeFactoryExitAnimation.h`（帧延迟 / 首帧 / 帧数 / 开合帧，`:10-55`）、`RuntimeFactoryAirExit.inl`（飞行器出厂）、`RuntimeFactoryExitClearance.inl`。
4. 免费单位 / 赠送交付：`RuntimeFreeUnitDelivery.inl`；克隆仓交付：`RuntimeCloningDeliveries.inl`、`RuntimeClonePendingDeliveriesSave.inl`。

### 5.3 移动

1. 行为记录 `RuntimeObjectBehavior`（`RuntimeObjectBehavior.h:38-92`）：`kind` 为 `Move/Attack`，`state` 为 `Idle/Queued/Moving/Blocked/Chasing/Attacking/Cooldown/Complete`（`:12-27`）。
2. 地面运动学：启动加速 `RuntimeVehicleStartupMotion.h`（`Phase::Cruise/Accelerating/Braking`，`:39`）、到达制动 `RuntimeVehicleArrivalMotion.h`（制动距离 `brakingDistance = 2.0` 格，`:11`）；落地 / 启动记录 `RuntimeVehicleArrival.inl`、`RuntimeVehicleStartup.inl` 及其 Save 头文件。
3. 导航与占用：地面位姿占用 `RuntimeGroundPoseOccupancy.h`；步兵子格系统 `RuntimeSubcellSystem.h`；空位证明 `RuntimeMovementEmptyCellProof.*`。
4. 水面 / 两栖运动见 `src/simulation/movement/naval/` 与 `src/simulation/movement/ground/RuntimeGroundNavigation.inl`；飞行器运动见 `src/simulation/movement/aircraft/`。

### 5.4 战斗与开火

## 本章缺口

- 参考引擎未提供按原版单位名（如具体坦克 / 步兵型号）的运行时类型表；类型识别完全依赖规则 ID 与标志，本章不据原版印象补单位名。
- 海军、两栖、飞行器仅在移动模式与车道层面给出判定入口，其运动学、停靠、轰炸 / 运输逻辑留待后续专章展开。
- 物件级状态哈希（相对规则哈希）的具体混合函数未在本章定位到独立实现文件；存档格式以 `GameWorld.cpp:900-1013` 的序列化记录为准。
- `src/simulation/combat/damage/RuntimeCrewSurvivors.inl` 为仅含 include 的空文件，乘员逃生主体逻辑在会话战斗层（`RuntimeSessionCombat.cpp:17573-17672`）。
- 部分 `.inl` 文件仅保留注释与时间线 codec 入口，具体算法实现落在对应 `.cpp` 或会话层头文件；本章已按实际出处标注。
