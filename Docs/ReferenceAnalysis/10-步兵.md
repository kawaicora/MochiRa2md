# 10 · 步兵

## 本章覆盖范围

本章按规范第 5 节的固定小节模板，梳理参考引擎中步兵类单位的类型判定、运行时数据、规则键、能力挂载、移动导航、战斗开火、生命等级、视野、动画帧选择、绘制流程、声音、持久化、AI 接入点与缺口。

**前提重申（见 [09-单位总览与分类.md](09-单位总览与分类.md) 第 1 节）：** 参考引擎没有独立的 `RuntimeInfantry` C++ 类；步兵运行时物件与所有其他单位一样是 `WorldObjectInstance`（`src/world/model/GameWorld.h:98`），种类为 `WorldObjectKind::Infantry`（`GameWorld.h:16`）。步兵与载具 / 飞行器在规则层共用 `UnitType` 结构（`src/data/rules/RulesDatabase.h:503`），差异由规则列表归属、`objectKind` 字符串、规则标志与移动系统归属推导。

## 1. 章节定位

- 规则段前缀：`InfantryTypes` 列表段中的每个 ID 段（`RulesDatabase.cpp:2954`）。
- 规则结构：`UnitType`，装载函数 `loadUnitType`，`objectKind = "infantry"`（`RulesDatabase.cpp:3813-3818`、`:5455-5456`）。

## 6. 移动与导航

### 6.1 移动模式

- 步兵默认地面轮廓；`runtimeUnitMovementModeProfile` 对步兵无 `naval` / `waterBound` / 空中标志时返回 `PathMovementMode::Ground`（`RuntimeMovementClassification.h:93-104`）。
- 通行百分率：步兵或 `speedType=foot` / `movementZone=infantry` 取 `LandType.foot`（`RuntimeMovementClassification.h:120`）。
- 游泳姿态由渲染层按地形水面判定（见第 10 节）；规则侧水面相关声音键 `EnterWaterSound` / `LeaveWaterSound`（`RulesDatabase.cpp:4204-4205`）。

### 6.2 子格占用（步兵空格位）

- 步兵占用格内三个子格，活动子格顺序为 2 / 4 / 3：`RuntimeSubcellSystemState::activeSubCells()`（`RuntimeSubcellSystem.h:160`、`:41-43`）；子格号到位姿偏移映射 `worldInfantrySubCellOffset`（被 `RuntimeGroundPoseOccupancy.h:55/71` 引用）。
- 空位判定：`runtimeEmptySubcellHasAvailability` 按 2→slot1、4→slot2、3→slot4 位掩码，三格全占（`blocked == 7`）才不可用（`RuntimeEmptySubcellAvailability.h:20-36`）。
- 预留 / 提交 / 对账：`reserveForDestination` / `commit` / `release` / `reconcile`（`RuntimeSubcellSystem.h:188-218`）；批量预留按 mover ID 排序，与命令插入顺序无关，保证锁步 / 回放确定性（`RuntimeSubcellSystem.h:196-197` 注释）。
- 步兵空位证明辅助：`RuntimeInfantryEmptyCellAvailability.inl`（注释约定：仅在占用证明通过后查询，预留经原 API 走层 / 忽略自身 / 槽位顺序）。
- 落地段承诺：`runtimeInfantryOffsetStartsAtSourceSubcell`、`runtimeInfantryMoveUsesCommittedCorner`（`RuntimeCommittedGroundMotion.h:42-45`）。

### 6.3 寻路接入

- 行为记录 `RuntimeObjectBehavior`：移动目标、路径队列、路径请求待决、重规划 tick 等（`RuntimeObjectBehavior.h:38-92`）。
- 移动空位证明：`RuntimeMovementEmptyCellProof.*`；地面导航 `RuntimeGroundNavigation.inl`。
- 步行动画呈现状态保存：`RuntimeInfantryWalkSave.inl`（仅表现态插值，逻辑格与移动冷却在常规物件 / 行为记录中）。

## 7. 战斗与开火

- 开火时机与冷却：`weaponCooldownTicksRemaining`（`GameWorld.h:165`）；开火起始 tick `spriteFiringStartTick`（`GameWorld.h:169`）。
- 索敌 / 机会开火：`src/simulation/combat/targeting/RuntimeCombatDetails.*`、`RuntimeCombatOpportunityCandidates.inl`、`RuntimeCombatOpportunityRangeBound.inl`；主动索敌 / 反击规则键 `CanPassiveAquire`（兼容别名 `CanPassiveAcquire`）、`CanRetaliate`（`RulesDatabase.cpp:4071-4076`）。
- 进驻开火：进驻步兵使用 `OccupyWeapon` / `EliteOccupyWeapon`；进驻伤害 / 射速 / 射程系数在 garrison 配置中（`RuntimeGarrisonSystem.h:20-22`）。
- 炮口锚点：步兵炮口 FLH 锚点表见 `src/render/geometry/RuntimeInfantryMuzzleAnchors.inl`（按 Art 序列名 + 朝向表给出偏移）。
- 碾压关系：步兵作为被碾压方由 `Crushable` / `DeployedCrushable` 决定；碾压目标扫描在会话战斗层（诊断夹具见 `diagnostics/RuntimeCrushRepresentativeBlockerContract.inl`）。
- 开火临时视野：`RuntimeFireReveal.*`（见 09 章 6.4）。

## 8. 生命 / 等级 / 老兵状态

- 生命：`health`（`GameWorld.h:104`）；最大生命由规则 `Strength` 解析。
- 等级：`veterancy`（0/1/2）与 `veterancyExperience`（`GameWorld.h:119/123`）。
- 老兵能力表：`VeteranAbilities` / `EliteAbilities`（`RulesDatabase.cpp:3864-3876`）；能力枚举 `VeteranAbility`（`RulesDatabase.h:404-423`）：`Faster / Stronger / Firepower / Scatter / Rof / Sight / Cloak / TiberiumProof / VeinProof / SelfHeal / Explodes / RadarInvisible / Sensors / Fearless / C4 / TiberiumHeal / GuardArea / Crusher`。
- 医院 / 军械所服务：
  - 关系判定：步兵 + 同阵营 + 建筑为 `hospital` 或 `armory`，双方存活且有次数（`RuntimeInfantryServiceSystem.cpp:14-36`）。
  - 治疗：医院且生命未满 → 补满（`RuntimeInfantryServiceSystem.cpp:38-39/79-82`）。
  - 晋升：军械所且 `veterancy < 2` → 直接置为精英 2 级并清经验；即便规则 `Trainable=no` 也无条件晋升（`RuntimeInfantryServiceSystem.cpp:40/83-89`）。
  - 次数扣减：每次服务消耗建筑 `currentAmmo` 一次（`RuntimeInfantryServiceSystem.cpp:90`）；容量规则见 `runtimeInfantryServiceAmmoCapacity`（`RuntimeInfantryServiceSystem.h:46-63`）。
- 死亡 / 残骸：步兵死亡时间线 `RuntimeUnitDeathSave.inl`；死亡动画序列见第 10 节；病毒死亡走独立延迟粒子段（`RuntimeUnitDeathSave.inl:2-4` 注释；`RuntimeVirusDeath.inl`）。
- 逃生：步兵本身是建筑 / 载具乘员逃生的产物类型（`RuntimeSessionCombat.cpp:17652`）。

## 9. 视野

- 视野来源：规则 `Sight`；运行时 `sightForObject` 对 `WorldObjectKind::Infantry` 按 `"InfantryType"` 查询规则（`RuntimeVision.cpp:114-122`）。
- 老兵视野：能力含 `VeteranAbility::Sight` 时半径乘 `veteranSight`（`RuntimeVision.cpp:139-145`）。
- 兜底与上限：`Sight <= 0` 按 5 格；上限 64 格（`RuntimeVision.cpp:138/148-149`）。
- 隐身 / 反隐：`Cloakable` / `CloakingSpeed`（`RulesDatabase.cpp:3986-3991`）；传感器标志 `Sensors` / `SensorArray` / `SensorsSight`（`:3992-3994`）；伪装检测 `DetectDisguise` / `DetectDisguiseRange`。

## 10. 动画帧选择

### 10.1 Art 序列键表

步兵可消费的 Art 序列名（`src/data/art/ArtDatabase.cpp:393-435`）：`Ready`、`Guard`、`Prone`、`Walk`、`Panic`、`Shovel`、`Carry`、`Fire`、`FireUp`、`SecondaryFire`、`Down`、`Crawl`、`Up`、`FireProne`、`SecondaryProne`、`Idle`、`Idle1`、`Idle2`、`Die1`..`Die5`、`WetDie1`、`WetDie2`、`Swim`、`WetAttack`、`WetIdle1`、`WetIdle2`、`Deploy`、`Deployed`、`DeployFire`、`DeployedFire`、`DeployIdle`、`DeployedIdle`、`Undeploy`、`Paradrop`。

### 10.2 待机 / 移动 / 开火

- 待机帧偏移：`runtimeUnitIdleFrameOffset`；规则 `idleRate > 0` 时按 `idleRate` 步进取模，否则按 Art `standingFrames` 与序列延迟取模（`RuntimeUnitIdleAnimation.inl:29-41`）。
- 动画 tick：`runtimeUnitAnimationTick`；时空冻结 / 寄生瘫痪任务标签返回 0 帧（`RuntimeUnitIdleAnimation.inl:3-18`）。
- 步行动画：`Walk` / `Crawl`（卧倒移动）；步速帧速率由 `WalkRate` 规则键控制（`RulesDatabase.cpp:3948`）。
- 开火序列：`Fire` / `FireUp` / `SecondaryFire`；卧倒开火 `FireProne` / `SecondaryProne`。
- 恐慌姿态：`Panic`（标志 `Fraidycat`）；搬运 / 挖掘类姿态 `Carry` / `Shovel`。

### 10.3 游泳姿态

- 游泳判定 `runtimeInfantryIsSwimmingForRender` → `runtimeInfantrySwimmingWithMetadata`（`RuntimeInfantrySwimAnimation.inl:1-7`；实现 `RuntimeProductionResources.cpp:1374-1407`）：
  1. 非步兵、airborne、在桥上 → 不游泳；
  2. 取渲染位姿 `renderX/renderY`（无渲染位姿取逻辑 `x/y`），越界返回否；
  3. 有地形块时按 TMP 图像解析地形类型，水面陆地类型返回否；
  4. 最终按 `cell->isWater && !cell->isShore` 判定。
- 游泳序列：`Swim`、`WetAttack`、`WetIdle1`、`WetIdle2`（`ArtDatabase.cpp:423-426`）。

### 10.4 死亡序列

- 选择函数 `runtimeInfantryDeathSequence`（`RuntimeInfantryDeathAnimation.h:17-69`）：
  1. 按 `Image`（空则用 ID）+ 北极地替代 Art 查 Art 类型，回退查类型 ID；VXL 体素 Art 直接返回空（`:25-33`）。
  2. 变体选择：`notHuman` 时 `infDeath` 夹到 1..5，否则 `infDeath == 2` 取 2、其余取 1（`:34-35`）。
  3. 候选序列名：水中先取 `WetDie1` / `WetDie2`，再回退 `Die<variant>`、`Die1`、`Die2`（`:37-39`）；`Die3/4/5` 的单帧占位（startFrame 0、frameCount 1、facingMultiplier 1）被跳过（`:50-54`）。
  4. 朝向桶：步兵源精灵自屏幕北方逆时针排布，`reversed = (256 - (facing % 256)) % 256`，再按 Art `facings`（缺省 8，夹到 1..32）分桶（`:55-59`）。
- 弹头死亡类型：弹头键 `InfDeath`（`RulesDatabase.cpp:5364`）；全局死亡动画表 `InfantryExplode` / `FlamingInfantry` / `InfantryHeadPop` / `InfantryNuked` / `InfantryVirus` / `InfantryMutate` / `InfantryBrute` 等（`RulesDatabase.cpp:1954-1970`），查询接口 `getInfantryDeathAnim(int)`（`RulesDatabase.cpp:3346-3350`）。
- 病毒死亡：`InfantryVirus` 全局动画（`RulesDatabase.cpp:1950-1952`），毒气发射按 35 帧时间线（前 20 帧肿胀、21 帧起破裂）保留在死亡时间线上，不在死亡瞬间生成有害气体（`RuntimeVirusDeath.inl:1-3`）。

### 10.5 特殊状态帧

- 部署态序列：`Deploy` / `Deployed` / `DeployFire` / `DeployedFire` / `DeployIdle` / `DeployedIdle` / `Undeploy`（`ArtDatabase.cpp:427-433`）。
- 时空 / 寄生冻结：任务标签 `chronofrozen` / `temporal` / `parasiteparalyzed` / `parasitestunned` 帧停在 0（`RuntimeUnitIdleAnimation.inl:15-16`）。
- 空投序列：`Paradrop`（`ArtDatabase.cpp:434`）。

## 15. 本章缺口

- 参考引擎未提供原版步兵单位名清单；本章行为原型全部以规则标志 / 系统名描述，未据原版印象补单位名。
- `RuntimeInfantryWalkSave.inl`、`RuntimeInfantryDeathRuntime.inl`、`RuntimeInfantryServiceRuntime.inl`、`RuntimeInfantryEmptyCellAvailability.inl` 当前为注释 / 空实现骨架，权威逻辑分别落在会话层、服务系统 `.cpp` 或占用系统 `.cpp`；复刻时需以实际调用点为准。
- 步兵游泳仅为渲染姿态判定；水面航行式移动（Naval 模式）不作用于步兵。
- 卧倒触发条件（何种规则 / 动作把 `prone` 置位）在生产源码中未定位到独立规则键；`prone` 为运行时姿态，Art 序列 `Prone` / `FireProne` 已解析，具体置位条件需后续在会话战斗 / 行为层核对。
- 步兵专属碾压反击、匍匐速度系数等细分数值规则键未在 `loadUnitType` 中单独定位到；现有碾压判定以 `Crusher` / `Crushable` / `OmniCrusher` 标志为准。
- 步兵 SHP 的朝向帧数、帧速率、锚点偏移等美术细节归 05a 解码章与后续 17 渲染章，本章未展开。
