# 15 · 建筑

## 本章覆盖范围

本章按规范第 5 节固定小节模板，梳理参考引擎中建筑类单位的类型判定、运行时数据、规则键、能力挂载、生产与出厂、各功能子系统、战斗防御、视野、动画帧选择、绘制流程、声音触发、持久化与 AI 接入点。

**前提重申（见 [01-源码清单与类层次.md](01-源码清单与类层次.md) 第 4 节）：** 参考引擎**没有**为建筑建立独立 C++ 继承树，也不存在 `RuntimeBuilding` 之类的独立实体类。建筑运行时物件与步兵 / 载具 / 飞行器一样是 `WorldObjectInstance`（`src/world/model/GameWorld.h:98`），种类为 `WorldObjectKind::Structure`（`GameWorld.h:14`）；规则层结构为 `BuildingType`（`src/data/rules/RulesDatabase.h:791-1020`），装载函数 `RulesDatabase::loadBuildingType`（`RulesDatabase.cpp:4306-4819`）。建筑之间的差异全部由规则标志 + 归属功能子系统（生产 / 防御 / 供电 / 经济 / 进驻 / 维修 / 碾压 / 大门 / 碉堡等）推导，禁止按原版印象虚构类名。

## 5. 建造与出厂

### 5.1 生产车道归属

1. 建筑规则经 `runtimeProductionLaneForBuilding` 分车道：`BuildCat=combat` 归 `Armory`，其余归 `Structures`（`RuntimeProductionLanes.cpp:241-247`）。
2. 六条车道枚举：`Structures=0`、`Armory=1`、`Infantry=2`、`Vehicles=3`、`Aircraft=4`、`Ships=5`（`RuntimeProductionLanes.h:18-25`）；同 tick 抢最后一笔资金时的推进顺序为 Structures → Armory → Infantry → Vehicles → Ships → Aircraft（`RuntimeProductionLanes.h:40-48`）。
3. 车道容量：`Structures` / `Armory` 保留原始单件契约，容量恒为 1（`RuntimeProductionLanes.cpp:305-307`；注释 `RuntimeProductionLanes.h:192-194`）。
4. 工厂车道匹配：`Factory=BuildingType` 同时服务 Structures 与 Armory；`Factory=UnitType` 按 `naval` 分流 Vehicles / Ships；其余类型对应 Infantry / Aircraft / Ships（`RuntimeProductionLanes.cpp:266-290`）。

### 5.4 完成、待放置与出厂衔接

1. 活动订单完成时，若 `requiresPlacement`，订单移入 `ready` 槽并发出 `PlacementReady` 事件；否则留在 `active` 槽直到宿主提交世界变更，防止出厂被堵时丢单或重复生成（`RuntimeProductionLanes.cpp:607-624`；注释 `RuntimeProductionLanes.h:247-250`）。
2. `PlacementReady` 事件由会话层转为侧栏状态文案，并播放建造完成提示音（`RuntimeSessionProduction.cpp:8502-8508`）。
3. 完成订单枚举 / 窥视 / 提交 / 消费接口：`runtimeEnumerateCompletedProduction`、`runtimePeekCompletedProduction`、`runtimeCommitCompletedProduction`、`runtimeConsumeReadyProduction`（`RuntimeProductionLanes.h:251-271`）。
4. 出厂租约：`RuntimeFactoryDeliveryState` 维护 `RuntimeFactoryDeliveryLease`（宿主 ID、车道、订单序号、产物 ID、集合 tick、集结格点、域）；陆地工厂用合成门位 `-1` 占门，海军工厂用唯一地基位 `0`（`RuntimeFactoryDeliveryState.h:35-48`）。获取否决枚举 `RuntimeFactoryDeliveryAcquireVeto`（含容量满 / 维修厂占用 / 工厂占用 / 订单或对象已租等，`RuntimeFactoryDeliveryState.h:50-58`）；释放原因枚举 `RuntimeFactoryDeliveryReleaseReason`（`:75-86`）；对账 `reconcile`（`:119-131`、`:153-155`）。
5. 被堵的免费交付（`FreeUnit` / 赠予建筑）作为交付义务挂起：`RuntimePendingFreeUnit`（宿主、阵营、建筑类型、单位类型），`deferFreeUnit` / `completeFreeUnit`（`RuntimeFactoryDeliveryState.h:15-20`、`:165-167`）。

- 武器集：`Primary/Secondary/ElitePrimary/EliteSecondary` + 编号 `WeaponN/EliteWeaponN`，装载末尾归集进 `WeaponSet weaponSet`（`RulesDatabase.cpp:4385-4411`、`:4739-4755`）；武器 / 投射物 / 弹头规则解析见 03 章 4.3-4.5 节。

### 7.2 围墙作为覆盖物的战斗

- 围墙在参考引擎中**不是** `WorldObjectInstance`：`Wall=yes` 的覆盖物保留地形归属值，不提升为世界物件（`RuntimeOverlayWallCombat.inl:1-2`）。
- 覆盖物围墙状态镜像存于 `TerrainCell.overlayWall`（`OverlayWallState { originalIndex, originalFrame, originalType, originalImage, health }`，`GameWorld.h:19-26`）；初始化 `initializeWorldOverlayWallState`（`GameWorld.h:46`）。
- 点选攻击：`visibleTerrainWallTargetAtPoint` 在普通结构 / 机动单位 / 前景飞机命中之后，作为空地基兜底回落到可见围墙像素；候选目标须可见且当前选择集内存在有伤害 / 有射程 / 可对地武器（`RuntimeOverlayWallCombat.inl:30-80`）。
- 围墙规则侧：建筑规则 `Wall`（`RulesDatabase.cpp:4506`）用于建筑类围墙链延伸；覆盖物规则 `Wall` 在 `OverlayType`（03 章 4.7 节，`RulesDatabase.cpp:5017`）。

### 7.3 自爆 / 死亡武器衔接

- `Explodes`、`DeathWeapon`、`DeathWeaponDamageModifier`、`Explosion`、`DestroyAnim` 规则在死亡流程中被消费；具体伤害结算、弹头效果与残骸生成见后续 18 章（战斗 / 伤害模块 `src/simulation/combat/damage/`）。

## 15. 本章缺口

1. **多个建筑子系统 `.inl` 为空占位**：`RuntimeBuildupRuntime.inl`、`RuntimeBuildingCollapseRuntime.inl`、`RuntimeBuildingCollapseSave.inl`、`RuntimeBuildingRevealSave.inl`、`RuntimeFoundationCollision.inl`、`RuntimeBuildingDeparture.inl`、`RuntimeGrindingEntryFeedback.inl`、`RuntimeGrindingAnimationSave.inl`、`RuntimeInfantryServiceRuntime.inl`、`RuntimeRepairDepotDockPose.inl`、`RuntimeStructureRepackRuntime.inl`、`RuntimeTankBunker.inl` 当前仅含注释或空行；其运行时实现位于会话壳层 / 其他模块，本章按可见接口与字段标注，未在这些文件内见到函数体。
2. **建筑生产规划 AI 未实现**：`src/simulation/ai/` 生产源码无独立建筑基地规划 / 防御补位决策器；相关用例为 `diagnostics/RuntimeComputerBasePlanSmoke.inl` 夹具。AI 自动选址、建造顺序、防御排布的接入点待后续 AI 章节补齐。
3. **倒塌 / 废墟持久化实现未在本目录见到**：`RuntimeBuildingCollapseSave.inl` 为空；废墟对象如何在存档中以 `rubble` 身份恢复、残骸（Debris）对象的生成与回收链路需对照世界对象创建 / 序列化章节（08 章）复核。
4. **地基碰撞具体规则未展开**：`RuntimeFoundationCollision.inl` 仅注释；建筑地基占用格、不可通行行（`NumberImpassableRows`）与机动体通行判定的结合点在导航占用模块，本章未逐函数对照。
