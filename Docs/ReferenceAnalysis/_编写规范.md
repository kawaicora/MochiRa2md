# 编写规范（所有章节作者必须先读）

本目录文档用于指导 Unity 工程复刻《红色警戒2：尤里的复仇》，唯一事实依据是只读参考引擎源码。

## 1. 路径与硬约束

- 只读参考源码根：`D:\___SYSTEM_PATH\source\repos\ConcordRTS\`（下文引用时相对该根，写作 `src/...`）。**严禁**在该目录及其 `Mochi` 关联目录内写入、新建、修改任何文件；只用 Read / Grep / Glob 读取。
- 文档输出根：`D:\UnityProject\Ra2md\Docs\ReferenceAnalysis\`，新 Markdown 一律写在这里。
- Unity 工程 `D:\UnityProject\Ra2md` 下除本 Docs 目录外，**不得**改工程代码、`package.json`、版本号、配置文件。
- **不要**启动 Unity 编辑器实例，不要运行参考工程构建；只做静态阅读与文档撰写。
- 本任务只写文档，不写复刻实现代码（附录只给 Unity 落点建议，不贴实现代码）。

## 2. 称呼与引用格式

- 文档内部对参考工程统一用中性称呼「参考引擎」，**不要**在产物中写出参考仓库原名。
- 每条关键结论必须可回溯到源码，引用格式：`src/<模块>/<文件>:<起始行号>`，例如 `src/world/model/GameWorld.h:98`。
- 多文件支撑时逐条列出；行号以你实际 Grep/Read 到的为准，不得编造行号。
- 规则 INI 键名、资源名、类名、字段名、枚举值一律原样照抄（区分大小写），不要翻译改写。

## 3. 禁止猜测与缺口标注

- 源码读不到、参考引擎未实现、接口为空实现、被 `diagnostics/`/`Smoke` 测试夹具占据的位置，必须明确写「参考引擎未实现 / 未找到 / 仅测试夹具」，禁止用原版 RA2 印象或常识填充。
- 若某机制在源码中存在但不完整（README 自述保留的历史问题），照实标注「参考引擎当前状态：……」。
- 区分：生产源码（`src/` 下 `.h/.cpp/.inl`）、测试夹具（`tests/`、`diagnostics/`、`*.Smoke.*`）、示例（`samples/`）。只有生产源码结论才能作为引擎行为依据；测试夹具只用于佐证格式约定。

## 4. 文档体裁

- 中文，Markdown。流程必须步骤化（第一步…第二步…）；类与字段列「名称 / 类型 / 含义」表格；字节布局用表格或代码块逐字节说明。
- 每章开头给「本章覆盖范围」和「对应源码目录」，结尾给「本章缺口 / 参考引擎未覆盖项」小节。
- 章节间互链用相对路径 Markdown 链接。
- 单位/对象类必须先从源码真实类名、结构体名、`data/rules` 规则段与 INI 键提取清单，再分章；**不得凭空编造单位名**。参考引擎是规则驱动的系统式实现，运行时物件由 `src/world/model/GameWorld.h` 的 `WorldObjectInstance` 统一承载，步兵/载具/海军/两栖/飞行器/建筑由规则标志与系统归属区分；如源码中确无独立 C++ 类，照实说明，不要虚构继承树。

## 5. 单位类章节固定小节模板（每章必须覆盖）

1. 章节定位：该类单位在参考引擎中的真实归属（规则段前缀、系统模块、渲染模块）。
2. 类型判定：源码用哪些 INI 键 / 标志位 / 枚举把单位归入本类（附键名与取值、出处行号）。
3. 运行时数据：`WorldObjectInstance` 及相关运行时结构字段表（名称 / 类型 / 含义 / 出处）。
4. 所属规则 INI 段：段名前缀、关键键名清单（摘自 `data/rules` 解析代码）。
5. 能力与武器挂载：能力系统、武器/弹头/投射物接入点。
6. 移动与导航：移动类型、地形通行、寻路接入点。
7. 战斗与开火：开火时机、炮身/炮塔/炮管、射程、俯仰、临时视野。
8. 生命 / 等级 / 老兵状态：生命、残骸、等级、勋章。
9. 视野：视野来源、等级视野倍率、开火临时视野。
10. 动画帧选择：待机 / 移动 / 开火 / 受损 / 死亡 / 特殊状态的帧选择规则与出处。
11. 绘制流程：SHP 还是 VXL、朝向帧、阴影、选框、辅助动画。
12. 声音触发：事件名 / CRC 映射与触发时机。
13. 保存 / 恢复字段：序列化顺序与哈希接入点。
14. AI 行为接入点：AI 如何决策、命令接入。
15. 本章缺口：未实现 / 未找到项。

## 6. 源码阅读提示

- 大量实现写在 `.inl` 头文件与 `.h` 内联定义中，`.cpp` 很少；检索时务必覆盖 `.h/.hpp/.inl/.cpp`。
- `diagnostics/` 目录与文件名含 `Smoke`、`Contract`、`TestHook` 的是测试/诊断代码，引用生产行为时注意排除。
- `src/data/rules/ProductionRulesLoader.cpp` 是 INI 字段→规则对象映射的主入口；`src/assets/archive/` 是 MIX/VFS；`src/assets/codecs/` 是 PAL/SHP/TMP；`src/audio/` 是音频；`src/ui/` 与 `src/runtime/menu/` 是菜单；`src/render/` 是绘制。
- 命令行与配置入口见 `src/runtime/config/`、`src/runtime/host/`、`API.md` 与 `samples/runtime_config.example.ini`。

## 7. 交付自检

- 写完后自查：每个关键数字/键名/类名是否有行号出处；缺口小节是否存在；是否有编造内容；文件是否落在本目录。
